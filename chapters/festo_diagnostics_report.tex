\section{Introduction}

In this report, the diagnostic extension of the FESTO Processing Station is presented. The station makes a basic industrial automation routine where a part is located in the socket, the test socket/table transports it, the part is drilled, checked by the testing cylinder, and taken to its final destination.

The program of automatic operation of the station already worked successfully. The task was to introduce a diagnostic system for possible errors and notify the operator about them via indicator lamps.

The diagnostic extension was designed for the older FESTO/FST software that ran on Windows XP. For this reason, the program was created using simple PLC logic, timers, flags, and comparison blocks without any special libraries.

\section{Executive Summary}

Five types of possible errors were programmed for the FESTO Processing Station. They correspond to the most likely failures of the equipment: no material in the socket, test socket transport error, drill cylinder error, testing cylinder error, and stop/ emergency stop condition.

Moreover, an additional function of diagnostics override was introduced. Once the error occurred during the cycle after its automatic start, the operator can press the button Input I2.2 to bypass the current diagnostic and go to the next step. Override is impossible if the automatic cycle is yet to start, and it also cannot be done for stop/e-stop conditions.

\section{Station Description}

The major components of the FESTO Processing Station include: socket, drilling slot, drill, test socket and testing cylinder, and final slot.

\begin{longtable}{|p{1.2cm}|p{4.4cm}|p{7.4cm}|}
\hline
Label & Station Part & Function \\
\hline
A & Part taking slot / socket & Initial position where the part is detected \\
\hline
B & Drilling slot & Position where the part is held and drilled \\
\hline
C & Drill & Performs the drilling operation \\
\hline
D & Test socket / testing cylinder & Checks the drilled hole \\
\hline
E & Final slot & Final output position of the processed part \\
\hline
\end{longtable}

A basic cycle starts when a part is put in the socket and the operator presses the Start button. Then, the test socket/table starts transporting it to the drilling slot, and when it is finished, the drill starts working. At first, the drill cylinder goes down, then the drilling process is done, and finally, the drill cylinder returns back to its upper position. The table transports the part to the testing slot, and the testing cylinder checks it. Then, the table transports the part to the final slot.

\section{Reset and Diagnostic Recovery Procedure}

Pressing the Reset button I2.1 turns off the diagnostic lamps, removes active diagnostic flags and blinking lamps, resets the timers, and resets the return override flags F1.1--F1.6.

It allows the operator to clear up the diagnostic code.

\begin{verbatim}
IF I2.1 'Reset / clear diagnostics
THEN RESET F0.0 'DIAG 1 - no part
     RESET F0.1 'DIAG 2 - test socket
     RESET F0.2 'DIAG 3 - drill cylinder
     RESET F0.3 'DIAG 4 - testing cylinder
     RESET F0.5 'DIAG 5 - stop or emergency
     RESET F0.6 'Diagnostic blink OFF phase
     RESET F0.7 'Diagnostic blink ON phase
     RESET F1.0 'Automatic cycle started / override allowed
     RESET F1.1 'Override return to step 8
     RESET F1.2 'Override return to step 16
     RESET F1.3 'Override return to step 18
     RESET F1.4 'Override return to step 25
     RESET F1.5 'Override return to step 31
     RESET F1.6 'Override return to step 1
     RESET O1.0 'Start LED
     RESET O1.1 'Reset LED
     RESET O1.2 'Positioning LED
     RESET T7
     RESET T8
     RESET T9
\end{verbatim}

\section{Diagnostic Override Function}

Additional diagnostic function was implemented using the input I2.2.

Normally, it serves to start positioning program. But once the automatic cycle is launched, it may work as a diagnostics override button.

It works depending on the state of the diagnostic flag F1.0. If it is not active (off), the automatic cycle has not started, and the override is not possible. If F1.0 is active, the override is permitted.

Thus, it prevents the operator from continuing processing without a part at the beginning, and also from overriding the stop and e-stop conditions.

\hline
Automatic cycle has not started & Normal positioning \\
\hline
Automatic cycle has started and a timeout fault occurs & Ignore fault and continue to stored next step \\
\hline
Emergency stop or Stop condition active & Override not allowed \\
\hline
No part detected before cycle starts & Override not allowed \\
\hline
\end{longtable}

\section{Detailed Fault Analysis}

\subsection{Fault 1: No Part Detected at Start}

\textbf{Root Cause Domain:} Process / Material

\textbf{Severity:} High

\textbf{Detection Type:} Instantaneous

\textbf{Diagnostic Flag:} F0.0

\textbf{Lamp Indication:} O1.0 blinking

The fault happens when the operator presses the start button, but the sensor I0.0 fails to detect a part in the socket.

Since there is no part, the automatic operation cannot safely proceed because it involves rotating, drilling and testing.

Root causes might include: no part in the socket, wrong part positioning, malfunctioning or dirty sensor I0.0, loose/damaged wires of the sensor, part too small to be detected by the sensor or faulty sensor input.

In order to solve the problem, the operator should ensure that there is a part in the socket and that it is well positioned. Then the operator should check the LED of I0.0 and clean the sensor if needed. Also, the wiring and connector should be checked. Then press reset I2.1 and Start I2.0 once the part is detected.

\hline
Trigger & I2.0 Start button pressed \\
\hline
Fault condition & I2.0 ON and I0.0 OFF \\
\hline
Diagnostic flag & F0.0 \\
\hline
Indicator & O1.0 blinking \\
\hline

\hline

   AND I2.7 'Emergency is reset
   AND N I0.0 'Part in socket

     SET P2 'AUTOMATIC
\end{verbatim}

\subsection{Fault 2: Test Socket Position Fault}

\textbf{Root Cause Domain:} Mechanical / Electrical / Sensor

\textbf{Severity:} High

\textbf{Detection Type:} Timer-based

\textbf{Diagnostic Flag:} F0.1

\textbf{Lamp Indication:} O1.0 + O1.1 blinking

The fault occurs when engine O0.2 gets energized, but sensor I0.1 fails to become active within the set time.

The table/test socket must reach its right position for further drilling/testing operation to proceed. Thus, if sensor I0.1 fails to confirm the right position, the process becomes out-of-order.

Root causes for the problem might include: jamming of the test socket/table, malfunctions in the motor or actuator which is operated with O0.2, malfunction in the position sensor I0.1, malfunction in the wiring and connector of I0.1, incomplete rotation of the test socket/table, insufficient power supplied to O0.2 and sensor I0.1 or mechanical blockage in the way of the table/test socket.

To solve the problem, the operator should check the physical rotation of the test socket/table, check whether the path is blocked, verify O0.2 with its indicator light and verify I0.1 with the help of its LED. The operator should also check whether I0.1 activates when test/socket comes into its position. The cable connecting the sensor and the PLC should also be checked. Once the problem is diagnosed, press Reset I2.1. Then press Override I2.2 to allow continuing if the process is already in motion.

\subsection{Fault 3: Drill Cylinder Fault}

\textbf{Root Cause Domain:} Pneumatic / Mechanical / Sensor

\textbf{Severity:} Critical

\textbf{Detection Type:} Timer-based and logical sensor conflict

\textbf{Diagnostic Flag:} F0.2

\textbf{Lamp Indication:} O1.0 + O1.2 blinking

The fault occurs when the cylinder fails to come to its position within the set time. The other possible fault is simultaneous activation of the upper and lower sensor.

It should never happen that the upper and the lower position sensors get activated simultaneously since it means some wiring or sensor problems.

The root cause for the fault might include: jamming of the cylinder, low pressure of the air in the drill chamber, malfunction of the solenoid valve O0.3/O0.4, malfunction of I0.4 or I0.5 position sensors, damage to wires from these sensors, slow moving cylinder, mechanical blocking in the drill cylinder or electrical short circuit resulting in activation of both position sensors.

Solving the problem involves: checking the air pressure supply in the drill cylinder, checking the mechanical condition of the drill cylinder. Also, the output O0.3/O0.4 should be verified. Moreover, the LEDs on I0.4 and I0.5 should be verified and ensure that only one position sensor works at any time. The cable should be inspected and any mechanical blockage be removed. After diagnostics, press Reset I2.1. If the automatic cycle had been initiated and the problem was timeout only, I2.2 can be used for override.

\subsection{Fault 4: Testing Cylinder Fault}

\textbf{Root Cause Domain:} Pneumatic / Mechanical / Sensor

\textbf{Severity:} High

\textbf{Detection Type:} Timer-based and logical sensor conflict

\textbf{Diagnostic Flag:} F0.3

\textbf{Lamp Indication:} O1.1 + O1.2 blinking

This fault happens when the testing cylinder is requested to move downwards, but the lower position sensor I0.7 is not detected within the acceptable period.

Testing cylinder is used for checking the drilled hole or confirmation of processed part. If the cylinder cannot reach the required position, there will be no confirmation of inspection performed.

The two testing cylinders sensors must never be active at the same time.

Possible faults include jammed testing cylinder, insufficient pneumatic pressure, broken or disconnected solenoid, clogged testing probe due to wrong positioning of a part, malfunctioning lower position sensor I0.7, wiring fault on one of sensors (I0.6, I0.7), both sensors detecting due to short circuit or misalignment.

To fix this problem, the operator needs to inspect the movement of testing cylinder and inspect the testing probe for any obstructions. The lower position sensor I0.7 and upper position sensor I0.6 should be inspected. It is also necessary to make sure that both sensors are never active simultaneously. Pneumatic tubing and valve need to be inspected as well. Once the problem is fixed, Reset I2.1 button needs to be pushed. The override signal I2.2 can be used if it is safe to continue the automatic cycle that has already started.

\subsection{Fault 5: Stop or Emergency Stop Condition}

\textbf{Root Cause Domain:} Operator / Safety

\textbf{Severity:} Critical

\textbf{Detection Type:} Instantaneous

\textbf{Diagnostic Flag:} F0.5

\textbf{Lamp Indication:} O1.1 blinking

This fault is triggered either by pressing of Stop button or lack of emergency stop reset condition.

This situation is considered a safety condition. The primary reason of displaying this warning is not merely diagnostics but making sure that operator inspects the machine before automatic cycle continues.

Root causes of the problem include pressing Stop during cycle, activation of emergency stop, absence of emergency stop reset condition, interruption of operation by operator due to unsafe condition, or machine condition requiring operator to perform some safety checks before operation can resume.

To resolve the fault, it is necessary to identify the reasons for pressing Stop and/or emergency stop condition activation. Any obstructions and other safety concerns should be resolved. Motion of the machine must be stopped completely by the operator before anything else. The operator needs to ensure that emergency stop circuit is released. After this, Reset I2.1 button needs to be pushed. Overriding of this diagnosis is explicitly forbidden.

\section{Diagnostic LED Control}

LED diagnostics is implemented in the compare block CMP2. There are three LEDs available which are blinking with the period of 1 second on and 1 second off.

The basic principle is that the diagnostic flag is raised, then the beginning of ON phase begins with F0.7 signal. Necessary combination of LEDs goes ON, then the ON phase ends after time period T7 and the LEDs go off. Afterward, F0.6 initiates the OFF phase which is terminated by T8 and cycle starts again.

This makes the problem more obvious since there is blinking of lights rather than constant lighting.

\hline

\hline
\end{longtable}

\section{Diagnostic Stop State}

If diagnostic problem appears during the automatic cycle, the program goes to Step 200. This ensures the disabling of all harmful and moving outputs so that the automatic cycle will not progress further without solving the problem.

Thus, the diagnostic state becomes much safer since there will be turning off of motion commands before any overriding attempts.

\begin{verbatim}
STEP 200
IF NOP
THEN RESET O0.1 'Drill engine
     RESET O0.2 'Test socket engine
     RESET O0.3 'Drill position down
     RESET O0.4 'Drill position up
     RESET O0.6 'Testing piston to lower position
     RESET T9 'Diagnostic movement fault timeout
     JMP TO 201
\end{verbatim}

\section{Diagnostic Override / Ignore Logic}

Diagnostic override logic is introduced at Step 201.

In case of any fault, an operator may choose to press Reset I2.1 to clear diagnostics and restart the program from Step 1 or press Positioning I2.2 to ignore the diagnostic fault and continue the program to the stored next step.

Nevertheless, Positioning I2.2 will serve as override only when F1.0 flag is active, which implies that the automatic cycle has been launched.

Specifically, in case of test socket fault in the earlier stage than Step 8, the F1.1 is activated by the program. Upon pressing the Positioning I2.2 button, the diagnostic fault is cleared and program moves on to Step 8.

The above scheme is repeated for other stored return points as well.

\section{Testing and Validation Procedure}

Validation of diagnostic functions took place by creating each of the mentioned faults and observing the behavior of corresponding flag, lamp pattern, and program flow. Test cases included station operation without the part, obstruction or disconnection of position sensors, inability of cylinders to reach the specified position, creation of contradictive state of the sensors, activation of Stop or Emergency Stop faults, and testing override in case of fault due to timeout.

Correct response was assumed when the proper diagnostic flag was activated, corresponding lamp pattern began blinking, and potentially dangerous outputs were deactivated if required.

Override logic was verified by making sure that only faults after starting of the automatic cycle could be ignored and that no override was possible before cycle start or during stop/e-stop situations.

\section{Safety Notes}

Diagnostic override can be useful for demonstration purposes or in case of intentional creation of faults during lab testing and for proceeding through the process once the malfunctioning sensor is identified.

It is critical to remember that if a cylinder does not reach its specified position, overriding will lead to a collision or incorrect drilling and testing operations.

Thus, no-part-at-start fault cannot be overridden, stop and e-stop faults cannot be overridden, reset is the only appropriate reaction in most cases, and override shall be performed only when operator knows about the safety of the next step.

\section{Conclusion}

In conclusion, this report described the implementation of the diagnostic system for the FESTO Processing Station. In addition to the existing automatic sequence, five additional diagnostic categories related to material absence, table positioning problem, drill cylinder fault, testing cylinder fault, and stop/e-stop conditions were added to the system.

Diagnosis was implemented utilizing all existing PLC resources, namely input sensors, output lamps, flags, timers, and compare blocks. Three existing output lamps were used for diagnostic purposes by changing their blinking patterns (O1.0, O1.1, and O1.2).

A controlled diagnostic override using Positioning button (I2.2) was also implemented to allow selected faults to be ignored only after the launch of the automatic cycle.

Overall, diagnostics greatly improve fault detection capability and provide valuable information for troubleshooting and system safety, while being fully compatible with older FESTO/FST4 environment and Windows XP-based programming.
